# 전처리 규칙

## 공통

- 원본 파일은 `data/raw`에 그대로 보관합니다.
- 원본 8개 파일은 `CHECKSUMS.sha256`과 대조합니다.
- 데이터 헤더와 스키마 XLSX의 컬럼명·원본 타입·기준일을 설정 파일과 비교합니다.
- 컬럼명은 PostgreSQL 호환을 위해 소문자로 통일합니다.
- 문자열은 앞뒤 공백만 제거하고 내부 내용은 임의 수정하지 않습니다.
- 빈 문자열과 `NULL`, `None`, `NaN`, `N/A` 표기는 결측값으로 통일합니다.
- 숫자는 쉼표를 제거하고 `NUMERIC` 정밀도를 유지합니다.
- 숫자·날짜 변환에 실패한 값은 `NULL`로 처리하고 프로파일의 `invalid`에 집계합니다.
- 모든 행에 원본 행 번호, 원본 파일명, 데이터셋 스냅샷 기준일을 추가합니다.

## 날짜

다음 형식을 `YYYY-MM-DD`로 통일합니다.

- `YYYYMMDD`
- `YYYY-MM-DD`
- `YYYY/MM/DD`
- `YYYY.MM.DD`
- `YYYY-MM-DD HH:MM:SS`

`99991231`은 거래 종료일 미정 등의 센티널일 수 있으므로 `9999-12-31`로 보존합니다.

## 적재 방식

상품군마다 별도 Python Worker 프로세스에서 정제합니다. 정제된 행은 표준 출력 CSV 스트림으로 PostgreSQL `COPY`에 전달되며, 대용량 중간 CSV를 프로젝트 폴더에 남기지 않습니다.

전체 적재는 하나의 데이터베이스 트랜잭션으로 실행됩니다. 컬럼 오류, 행 수 불일치, 필수값 누락, 뷰 생성 실패가 발생하면 전체 변경을 롤백합니다.

## 정확성

- 제공되지 않은 보수·수익률·기준일을 외부 값으로 자동 보완하지 않습니다.
- 채권 수익률과 ETF·펀드 기간 수익률을 같은 지표로 간주하지 않습니다.
- 상품 판매 여부와 거래 상태 원본 필드는 별도로 보존합니다.
- 상품 ID 중복은 클래스·판매 채널 차이일 수 있어 자동 제거하지 않습니다.
- 원본 이상값은 수정하지 않고 `quality_flags`로 표시합니다.
